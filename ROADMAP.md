# ROADMAP.md

# Memorix — Roadmap

Документ фиксирует дальнейший план развития Telegram-бота Memorix.

Главный принцип:

Сначала стабильность и полезность, потом масштабирование и монетизация.

---

# Этап 0. Стабилизация текущего MVP

Цель:

убрать runtime-ошибки, мусор в коде и нестабильные сценарии.

## Задачи

* Проверить все callback handlers.
* Проверить все FSM-состояния.
* Проверить `/cancel`.
* Проверить `⬅️ Назад`.
* Проверить удаление записей.
* Проверить очистку связанных сообщений.
* Проверить сохранение:

  * текста
  * голосовых
  * кружков
  * фото
  * альбомов
  * видео
  * документов
  * постов из Telegram-каналов

## Критерий готовности

Бот проходит полный ручной тест без ошибок в Railway logs.

---

# Этап 1. Полноценная работа с файлами

Цель:

не просто сохранять файлы, а извлекать из них смысл.

## PDF

* Сохранять PDF как файл.
* Извлекать текст из PDF.
* Добавлять извлечённый текст в память.
* Использовать текст PDF в поиске.
* Показывать PDF в `📄 Полностью`.

## DOCX

* Извлекать текст из DOCX.
* Добавлять текст в память.
* Искать по содержимому документа.

## XLSX

* Извлекать названия листов.
* Извлекать первые строки таблиц.
* Сохранять краткое описание.
* Использовать содержимое в поиске.

## PPTX

* Извлекать текст со слайдов.
* Использовать текст презентации в поиске.

## Критерий готовности

Пользователь отправляет PDF/DOCX/PPTX/XLSX, а потом может найти его по словам внутри файла.

---

# Этап 2. OCR для изображений

Цель:

сделать изображения searchable.

## Задачи

* OCR для обычных фото.
* OCR для скриншотов.
* OCR для изображений из Telegram-постов.
* OCR для HEIC, если возможно.
* Сохранять распознанный текст отдельно.
* Использовать OCR-текст в поиске.

## Критерий готовности

Пользователь отправляет скриншот, а потом находит его по тексту на изображении.

---

# Этап 3. История версий записей

Цель:

дать возможность видеть, что менялось.

## Задачи

* Создать таблицу `memory_versions`.
* При каждом редактировании сохранять старую версию.
* Добавить кнопку `🕓 История`.
* Показывать список версий.
* Позволить восстановить старую версию.

## Критерий готовности

После редактирования записи старая версия не теряется.

---

# Этап 4. Улучшение поиска

Цель:

сделать поиск быстрее, дешевле и точнее.

## Гибридный поиск

Сначала использовать:

* теги
* категории
* типы контента
* keyword search

Только если результата нет — использовать AI.

## Semantic search

* Подготовить embeddings.
* Сохранять embedding для каждой записи.
* Искать похожие записи через векторный поиск.
* Уменьшить количество GPT-запросов.

## Критерий готовности

Большая часть поисков выполняется без GPT, но качество остаётся высоким.

---

# Этап 5. Оптимизация расходов

Цель:

снизить себестоимость одного пользователя.

## Задачи

* Rules-first категоризация.
* GPT fallback только при неопределённости.
* Ограничения на AI-функции в Free.
* Лимиты на транскрипцию.
* Поиск более дешёвого STT.
* Кэширование результатов AI.
* Подсчёт AI-действий пользователя.

## Критерий готовности

Бесплатные пользователи не могут сжечь бюджет API.

---

# Этап 6. Free / PRO

Цель:

подготовить монетизацию.

## Free

Доступно:

* сохранение текста
* фото
* видео
* документов
* тегов
* категорий
* закреплений
* базового поиска

Ограничено:

* AI-поиск
* голосовые
* AI-сводки
* AI-чат

## PRO

Доступно:

* больше AI-запросов
* больше транскрипций
* AI-чат по памяти
* AI-сводки
* расширенный поиск
* экспорт
* история версий

## Цена

Стартовая цена:

199 ₽ / месяц

# Этап 7. AI-чат по памяти

Цель:

превратить Memorix из архива в личного ассистента.

## Примеры запросов

* Что я сохранял про машину?
* Собери все идеи по проекту.
* Что важного было за неделю?
* Какие мысли повторяются чаще всего?

## Критерий готовности

Бот отвечает не просто списком записей, а связным summary по памяти.

# Этап 10. Рефакторинг

Цель:

разобрать большой `bot.py` на модули.

Важно:

рефакторинг делать только после стабилизации MVP.

## Возможная структура

* handlers/
* services/
* db/
* keyboards/
* ai/
* utils/

## Критерий готовности

Код становится проще поддерживать, но поведение бота не меняется.

---

# Не делать сейчас

До стабилизации MVP не делать:

* веб-приложение
* сложный личный кабинет
* интеграцию с Notion
* интеграцию с Google Drive
* сложные CRM-функции
* масштабный рефакторинг
* смену стека
